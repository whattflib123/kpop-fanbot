# 追星機器人：分階段開通教學

適用 `qwer-update`（QWER 實際在跑的版本）和通用模板 `kpop-fanbot`。兩個 repo 程式同源，差異列在最後一節。

開發分兩階段，每階段都能獨立上線：

| 階段 | 做什麼 | 要申請的東西 | 要付費的東西 |
|---|---|---|---|
| 第一階段 | 追 YouTube＋Weverse，Claude 翻成繁中，推 Telegram 頻道 | Telegram bot、Claude API key | Claude API（每團每月約 US$1～3） |
| 第二階段 | 追 Instagram；TG 推完同步發 Threads（發前 TG 審核） | Meta 開發者 app、Threads 測試人員、IG 專業帳號＋FB 粉專 | 無 |

YouTube 和 Weverse 不用任何帳號或 key。IG 和 Threads 都走 Meta，可以共用同一個開發者 app。

---

## 階段 0：共同準備（兩階段都要）

1. **Clone repo、裝環境**
   ```bash
   python -m venv .venv && .venv/bin/pip install -r requirements.txt
   cp .env.example .env
   ```
2. **`.env` 規則**
   - 不進 git。
   - 值後面**不要**寫行內註解（`KEY=xxx   # 說明`）。docker `env_file` 會把 `# 說明` 當成值，空的 token 會變成亂碼（Threads 會報 `Invalid OAuth access token`）。註解放上一行。
3. **`config.json`**：要追的團、頻道、社群、IG 帳號、hashtags。不要的來源整段刪掉。Threads 只想轉發部分平台就設 `threads_sources`（例如 `["weverse"]`），沒寫 = 全部。
4. **`glossary.json`**：團名、成員名、粉絲名的固定譯名（原文 → 譯名）。Weverse 作者名用官方英文名，不用設。
5. **部署主機**：任何有 Docker 的機器。`data/` 是 volume，放 `state.db`（看過的內容、佇列）和 `threads_token.json`，搬家要一起搬，不然會重新初始化。
   - 遠端主機用 `deploy.py`（模板）或 `deploy_nas.py`（qwer-update），SSH 推檔＋`docker compose up -d --build`。本機要有 `paramiko`。
6. **第一次跑的行為**：每個來源第一次抓到的既有內容只記錄、不推播，之後只推新的。所以上線前先 `--dry-run` 看抓到什麼，確認頻道／社群 ID 沒抓錯。

## 第一階段：YouTube＋Weverse → Telegram

### 1-1 Telegram（必要）
1. 找 [@BotFather](https://t.me/BotFather)，`/newbot` 建 bot，拿 token → `.env` `TELEGRAM_BOT_TOKEN`。
2. 開一個頻道，把 bot 加成**管理員**，要有發文權限。
3. `TELEGRAM_CHAT_ID`：公開頻道填 `@頻道名`；私人頻道是 `-100` 開頭的數字（把頻道訊息轉給 [@userinfobot](https://t.me/userinfobot) 查，或用 `https://api.telegram.org/bot<TOKEN>/getUpdates`）。
4. `TELEGRAM_ADMIN_CHAT_ID`：你自己的個人 chat id。**先私訊 bot 一句話**（不然 bot 不能主動私訊你），再開上面的 `getUpdates` 網址看 `message.chat.id`。
   用途：翻譯失敗警示；第二階段的 Threads 發文審核也是私訊到這裡。
5. `BOT_NAME`：容器名和警示訊息開頭。同一台主機跑多個團要各取不同名字。

### 1-2 Claude API（必要）
1. [console.anthropic.com](https://console.anthropic.com) 建 API key → `ANTHROPIC_API_KEY`。
2. 帳戶要先儲值，額度 0 的話翻譯會失敗、不推播，並私訊你警示。
3. 模型固定 `claude-sonnet-5-5`（effort low；2026-11-04 從 Opus 換過來省錢，約 Opus 的一半）。每則約 US$0.001～0.01。

### 1-3 YouTube（免 key）
1. 找官方頻道的 **channel ID**（`UC` 開頭）：打開頻道頁 → 檢視原始碼搜 `channelId` 或 `externalId`。
2. **小心同名頻道**：例如 QWER 官方是 `@QWER_Band_official`，`@QWER_Band`、`@qwerband` 都是無關頻道。
3. 填進 `config.json` 的 `youtube_channels[]`（`id`、`label`）。
4. 機制：讀 RSS，RSS 偶發 404／500 時改抓頻道 `/videos`、`/shorts` 頁面，只取比已知最新一支還新的。標題用 videoId 去重（YouTube 會對標題做 A/B 測試，同一支標題可能不同）。

### 1-4 Weverse（免登入）
1. 查社群 ID（用網址路徑，例如 `weverse.io/qwer` 的 `qwer`）：
   ```bash
   .venv/bin/python -c "from sources import weverse; print(weverse.community_id('qwer'))"
   ```
2. 填進 `config.json` 的 `weverse_communities[]`：
   - `id`、`label`
   - 成員留言推播格式：`粉絲（或成員名）：被回覆的留言譯文` 換行 `成員：回覆譯文`，沒回覆別人就只有 `成員：譯文`（不加標題、AI 註記）。成員連回同一則留言時，同一輪（`.env` 的 `COMMENT_POLL_SECONDS`，預設 15 分）內的回覆會合成一則推。
   - `notices`：`true` = 也抓官方公告（Notice 分頁）。
   - `lives`：`true` = 也推成員直播通知（Live 分頁）。只推 TG 頻道，不發 Threads／FB、不審核；每場只推一次（開播時「🔴 正在 Weverse 直播」＋翻譯標題＋縮圖＋連結）。直播太短、bot 輪詢到時已結束，就改推「📺 直播已結束，可看回放」。延遲最多一個輪詢週期（`POLL_SECONDS`，預設 5 分）。
   - 直播回放自動存檔（`live_archive.py`，選用）：`.env` 設 `LIVE_ARCHIVE_DIR`（容器內路徑，例如 `/app/data/weverse_live`，或在 compose 另外掛一個 NAS 資料夾）就開。推過開播通知的直播，回放出來就在背景跑 `yt-dlp`，一次一支：最高畫質 mp4＋`ko_KR`／`zh_TW` 官方字幕 vtt＋`info.json`，檔名 `日期_成員_標題_postId`。回放還在轉檔就每輪重試，24 小時還失敗就放棄並私訊 admin；會員限定不存；存好私訊「📼 已存檔」。1 小時直播 1080p 約 600 MB。上線前的舊直播用 `docker exec -d <容器名> python live_archive.py backfill <communityId>` 補存（翻完整個直播分頁、新的先存、已有 mp4 跳過、可中斷重跑；進度在存檔資料夾 `.backfill.log`，跑完私訊 admin）。
   - `comments`：`false` = 只推貼文、不抓成員留言（沒寫 = 抓）。
3. 抓什麼：成員貼文（Artist 分頁）＋成員在自己貼文下的留言（最近 7 天）＋官方公告。不抓 Media 分頁（都是 YouTube 轉貼）。
4. 限制：成員在粉絲貼文底下的留言抓不到（那個 API 要登入）。原貼文我們沒推過（上線前既有、翻譯放棄）的留言不推，只記 seen；原貼文還在重試中的留言等下一輪。成員回粉絲的留言整則不推（TG／Threads 都不發，只記 seen）；回其他成員照推。其他成員（非貼文主人）直接留言先等 `COMMENT_HOLD_MINUTES`（預設 60）分鐘：期間有成員回它就不單獨推（回覆那則會帶出這句），沒人回才推。被回覆的留言已經推過（例如超過等待時間才回、或回貼文主人的直接留言）→ 接成討論串：TG／Threads 掛在那則留言推播底下，只放回覆，不重複引用原句（`comment_heads` 表記合併推播的第一則，`tg_messages` 也存留言的 message_id）；被回覆的留言沒發上 Threads 的話這則也不發 Threads。Weverse 是非公開網頁 API，HMAC key 從前端 JS 抓，401 會自動重抓；Weverse 改版可能會壞。

### 1-5 測試與上線
```bash
.venv/bin/python main.py --dry-run   # 只印會推什麼，不推、不寫 DB
.venv/bin/python main.py --once      # 跑一輪（第一輪只初始化、不推）
```
確認沒問題再部署：
```bash
docker compose up -d --build && docker compose logs -f     # 本機 Docker
python deploy.py            # 模板，遠端主機；連線資訊填 .env.deploy
python deploy_nas.py        # qwer-update，NAS；連線資訊讀 NAS_runner 的 .env
```

### 1-6 驗收清單
- [ ] log 有「初始化 ○○：記錄 N 則既有內容，不推播」，每個來源各一行。
- [ ] 私訊 bot 收得到警示（可暫時把 `ANTHROPIC_API_KEY` 填錯跑一輪，應收到翻譯失敗警示；記得改回來）。
- [ ] 等下一則新影片／貼文，頻道收到推播，格式：標題行＋中文譯文＋hashtag（YouTube 另附影片連結；Weverse 不放連結；IG 直接附影片＋照片和貼文連結，影片抓不到或超過 50MB 就改附縮圖）。
- [ ] 想重推某一則測格式：刪 `data/state.db` 的 `seen` 表那一列，下一輪會重抓重推（會真的推到頻道，先想清楚）。

## 第二階段：Instagram＋Threads

兩個都在 [developers.facebook.com](https://developers.facebook.com)，建一個 app 就夠。先做 Threads（簡單），再做 IG（步驟多、限流嚴）。

### 2-1 Threads 發文（選用）
1. 建 app → 使用案例選 **Threads API**，權限 `threads_basic`、`threads_content_publish`。
2. app 左側「應用程式角色」→ 新增 **Threads 測試人員**，填要發文的 Threads 帳號。
3. 到 **Threads app**（手機）→ 設定 → 帳號 → 網站權限 → **邀請** → 接受。沒接受會報 `The user has not accepted the invite to test the app`。
4. 回使用案例設定頁 → 產生存取權杖 → `.env` `THREADS_ACCESS_TOKEN`。Meta 後台產的通常已是 60 天長效；若是短效，把同頁 App Secret 填 `THREADS_APP_SECRET`，跑 `python threads_setup.py` 換長效。
5. 卡關點：Graph API Explorer 會要求 Facebook 登入，Threads token 不要從那裡拿，用使用案例頁的產生器。
6. 之後 bot 把 token 存在 `data/threads_token.json`，每 7 天自動 refresh。**換 token 時要先刪這個檔再部署**，不然會沿用舊的。
7. 發文規則：500 字上限、只放第一個 hashtag（Threads 一篇一個主題標籤，顯示時不帶 `#`，不是失敗）、圖 1 張 IMAGE／2～20 張 CAROUSEL。成員留言發成原貼文的回覆。超過 500 字切段接在回覆。
8. **發文前審核**：每篇貼文翻好先私訊 `TELEGRAM_ADMIN_CHAT_ID` 預覽＋按鈕「發佈／加評論／略過」。加評論 = 回覆 bot 的提示訊息，評論放貼文最前面、接「——— 以下為翻譯 ———」再譯文。另有「✏️ 改寫全文」（bot 傳整篇草稿、點一下複製，回覆改好的全文就照你的版本發，超過 500 字自動切段接回覆）和快速切換「去標題／只發評論／拿掉分隔線」（可多選，按了打勾；只發評論 = 不附譯文和續段，要再按加評論）。`THREADS_REVIEW_HOURS`（預設 24）小時沒回自動發；`THREADS_REVIEW=0` 關閉。TG 頻道不受影響照常推。
   注意：審核靠 bot 長輪詢 `getUpdates`，同一個 bot token 不能有第二個程式同時 `getUpdates`（會 409）。本機要用 bot 抓私訊時先停遠端容器。

### 2-2 Instagram（選用）
Business Discovery 只能用「自己的 IG 專業帳號」去查「別人的專業／創作者帳號」，目標帳號若是個人帳號查不到。

1. 你的 IG 切成**專業帳號**（創作者或商家）。
2. 建一個 **Facebook 粉絲專頁**，粉專設定 → 已連結的帳號 → 連結這個 IG。
3. 同一個 Meta app → 新增使用案例，選 Instagram、**透過 Facebook 登入**那個（不是 Instagram 登入）。
4. 工具 → **Graph API 測試工具** → 選 app → 取得使用者存取權杖，勾這四個：
   `pages_show_list`、`pages_read_engagement`、`instagram_basic`、`instagram_manage_insights`（要排程發 IG 短影音再加 `instagram_content_publish`）
   少最後一個會回 `#10 Application does not have permission`。登入時要勾選你的粉專和 IG。之前授權過沒出現選擇畫面：Facebook 設定 → 商業整合 → 移除 app 再重來。
5. `.env` 填 `META_USER_TOKEN`（剛拿到的）、`META_APP_SECRET`（app 設定 → 基本資料 → 應用程式密鑰）。
6. 跑
   ```bash
   .venv/bin/python meta_setup.py
   ```
   會換長效 user token → 取**不會過期的粉專 token** → 寫回 `.env` 的 `META_PAGE_TOKEN`、`META_IG_USER_ID` → 檢查 `config.json` 裡每個 IG 帳號都查得到。新版粉專不在 `me/accounts`，腳本改用 token 授權範圍裡的粉專 id。
7. `config.json` `instagram_accounts[]`：`username`、`author`（推播顯示名）、`label`（log 用）。
8. 限流：開發模式 app 額度很小，而且最先吃光的是「處理時間」（header `x-app-usage` 的 `total_time`），不是呼叫次數。所以 IG 每 `IG_POLL_SECONDS`（預設 900 秒）抓一次、每帳號最近 5 則；用量任一項 ≥80% 或回 `#4` 就跳過這輪。帳號多就把 `IG_POLL_SECONDS` 調大。
9. 抓不到：限時動態、廣播頻道、成員在別人貼文下的留言。影片／Reels 只推封面。
10. 改 FB 密碼或移除 app 授權會讓 token 失效，重做 4～6。

### 2-3 上線與驗收
1. 改好 `.env`、`config.json` 後重新部署（改這兩個檔和 `glossary.json` 都要重部署）。
2. 驗收：
   - [ ] log 有 IG 各帳號的初始化行、沒有 `#4`／`#10`。
   - [ ] 等下一則新貼文：先收到 TG 私訊審核預覽 → 按「發佈」→ 下一輪 log 「Threads 已發 … → media_id」→ Threads 帳號看到貼文。
   - [ ] 按「加評論」→ 回覆一段字 → 發出的 Threads 貼文開頭是你的評論＋分隔線。
   - [ ] 超過 500 字的貼文在 Threads 是一串回覆（續 2/N…）。

### 2-4 IG 短影音排程（選用）
1. 重拿 user token 時多勾 `instagram_content_publish`，跑 `meta_setup.py` 換粉專 token、重部署。
2. 本機排程：`python ig_schedule.py add 影片.mp4 --at "YYYY-MM-DD HH:MM" --caption-file ig.txt --threads-file threads.txt`；`list` 看狀態、`rm <id>` 取消。
3. 時間到 bot 發 Reels，私訊你 IG 連結＋Threads 文案；點連結 → 分享 → Threads，貼上文案。
4. 失敗：`list` 會顯示錯誤；`#10 Requires instagram_content_publish` = token 少權限；影片要 3 秒～15 分、建議 9:16 H.264。

## 常見錯誤速查

| 訊息 | 原因 | 解法 |
|---|---|---|
| 頻道沒收到、log 沒報錯 | 第一輪只初始化 | 正常，等新內容 |
| bot 私訊不到你 | 你沒先私訊過 bot | 先傳一句話給 bot |
| 翻譯失敗警示 | Claude 額度 0 或 key 錯 | 儲值／換 key，重部署 |
| `Invalid OAuth access token`（Threads） | `.env` 行內註解被當成值、或 token 過期 | 註解移到上一行；刪 `data/threads_token.json` 重部署 |
| `The user has not accepted the invite to test the app` | Threads 測試人員邀請沒接受 | 手機 Threads → 設定 → 帳號 → 網站權限 → 邀請 |
| `#10 Application does not have permission` | 少 `instagram_manage_insights` | 重拿 user token、跑 `meta_setup.py` |
| `#4 Application request limit reached` | IG 限流 | 等 15 分鐘，自動重試；調大 `IG_POLL_SECONDS` |
| Threads 一直沒發、log 沒報錯 | token 填到 `META_USER_TOKEN`（`TH` 開頭的是 Threads token） | 搬到 `THREADS_ACCESS_TOKEN`，重部署 |
| 換了 Threads token 還是 `Invalid OAuth access token` | `data/threads_token.json` 留著舊的（或行內註解產生的壞值） | 刪掉那個檔再重啟容器 |
| TG `409 Conflict: terminated by other getUpdates request` | 兩個程式同時用同一 bot token 長輪詢 | 停掉其中一個 |
| Weverse 401 一直重試 | HMAC key 改版 | 看 `sources/weverse.py` 的 key 抓取正則 |
| YouTube 推到奇怪頻道的影片 | channel ID 抓到同名頻道 | 重查 ID，刪 `seen`／`sources` 裡該來源的列重新初始化 |

## 維運
- 改 `config.json`／`glossary.json`／`.env` → 重部署。
- `data/` 搬家一起搬；清掉等於全部重新初始化（舊內容不會重推，但 Threads token 要重填）。
- Threads token 自動 refresh；Meta 粉專 token 不過期；Claude 額度要盯。
- 換團體：改 `config.json`、`glossary.json`、`.env` 的 `BOT_NAME`／頻道，`data/` 換新的。

## qwer-update 與模板 kpop-fanbot 的差異（2026-11-03 已同步程式）
| 項目 | qwer-update | kpop-fanbot |
|---|---|---|
| Weverse 官方公告、Threads 切段接回覆、發文前審核（`review.py`） | 有 | 有（2026-11-03 同步） |
| 部署腳本 | `deploy_nas.py`（讀 NAS_runner `.env`） | `deploy.py`（讀 `.env.deploy`） |
| 宣傳短影音 `promo/` | 有 | 無 |

之後 qwer-update 改了通用功能（`main.py`、`notify.py`、`notify_threads.py`、`review.py`、`translate.py`、`sources/`）要手動複製到模板，`deploy_nas.py`／`config.json`／`promo/` 不用。
